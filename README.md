# الزراعة النظيفة | دليل وإرشاد زراعي

موقع عربي ثابت باتجاه RTL، يعتمد ملفات HTML وCSS وJavaScript محلية. يضم دليل تغذية النبات والمحاصيل، إرشادات موثقة للأسمدة الحيوانية في تربة البيوت البلاستيكية، جداولاً مرجعية للطماطم والخيار بحسب المرحلة، وحاسبات تحويلية. لا يحتاج إلى قاعدة بيانات أو مفتاح API، ولا يتضمن مساعد ذكاء اصطناعي أو خدمة إرسال استشارات.

## التشغيل

افتح `public/index.html` مباشرة لتصفح الموقع والأدوات دون إنترنت. لتشغيل خادم محلي من جذر المشروع:

```sh
python3 -m http.server 3000 --bind 0.0.0.0 --directory public
```

افتح `http://localhost:3000`. تتطلب روابط المراجع الخارجية اتصالاً بالإنترنت. نموذج الاستشارة لتنظيم المدخلات محلياً فقط؛ لا يرسل البيانات ولا يحفظها.

## تعديل المحتوى بنفسك

عدّل **المصدر** ثم أعد البناء؛ لا تعدّل `public/index.html` وحده لأنه ملف مولّد وسيُستبدل. بيانات المحاصيل في `research/crops.json`، وموضوعات السماد الحيواني في `research/organic.json`، وجداول الطماطم والخيار في `research/greenhouse-schedules.json`. أضف للمعلومة الرقمية مصدراً واضحاً في حقل `sources`، واربطه عبر `sourceIds`. اكتب دائماً الوحدة، ونظام الزراعة، ومرحلة المحصول، والمنطقة أو نوع البيت الذي ينتمي إليه المرجع.

لإضافة محصول، أضف سجلاً يحوي `id` و`name` و`category` و`systems` و`focus` و`checks` و`sourceIds`. لإضافة مرحلة تسميد، أضف صفاً في جدول المحصول مع المرحلة والمدخلات والوحدة ومؤشر التعديل. لا تنقل جدولاً من تربة إلى زراعة دون تربة، ولا تحول ppm إلى كغ من منتج تجاري دون معرفة تحليل المنتج وكفاءة الحقن. لا تجعل القيمة الأجنبية جرعة سورية تلقائية؛ اترك ملاحظة النطاق والتحليل المحلي بجوارها.

لإضافة فقرة إرشادية، اكتبها في ملف JSON المناسب، وأضف مصدرها وتاريخ المراجعة في البيانات أو التقرير. لا تضع جرعات ثابتة للروث أو الأحماض أو خلطات الأسمدة لمجرد أن اسم المحصول معروف. يلزم تحليل التربة وماء الري والسماد العضوي، وقراءة EC وpH والصرف، ومراجعة مختص محلي قبل التطبيق.

## البناء والفحص

يتطلب البناء Python 3.10 أو أحدث، دون مكتبات إضافية:

```sh
python3 scripts/build_site.py
python3 scripts/check_site.py
npm test
```

بعد تعديل JavaScript شغّل أيضاً:

```sh
for file in public/assets/js/*.js; do node --check "$file"; done
```

ملف `src/index.template.html` هو مصدر الصفحة الرئيسية، وقالب الاستشارة في `src/consultation.template.html`. الأدوات التفاعلية في `public/assets/js/` وقسم الحاسبات في `src/farmer-tools-section.html`. عند تعديل سلوك البحث أو نموذج، أضف اختباراً مستهدفاً. ملف `public/manus-routes.json` يعلن المسارات المنشورة.

## النشر على GitHub Pages

استخدم الحزمة الكاملة المرفقة مع المشروع، ولا تنسخ مجلد `public` وحده. يجب أن تظهر في المستودع مجلدات `public` و`src` و`scripts` و`research`، ومجلد `.github/workflows` المخفي. إذا لم يظهر `research` أو لم يظهر تبويب **Actions** بعد الرفع، فهذه علامة على أن الرفع كان ناقصاً أو أن مجلد `.github` لم يُرفع.

أنشئ مستودعاً أو استخدم مستودعك المقصود، وارفع **محتويات هذه الحزمة** إلى جذره، بما فيها المجلد المخفي `.github`. لا ترفع ملف ZIP وحده. الفرع الافتراضي في إعداد النشر هو `main`؛ إن كان فرعك مختلفاً، عدّل `branches` في `.github/workflows/pages.yml`.

من إعدادات المستودع اختر **Settings → Pages → Source → GitHub Actions**. بعد رفع الملفات، ينفذ سير `pages.yml` بناء المحتوى وفحص روابطه ثم نشر مجلد `public`. سيظهر رابطك الفعلي في صفحة Pages ونتيجة سير Actions؛ الحزمة لا تعني أن النشر تم بالفعل.

الطريقة الأسلم: فك ضغط الحزمة على جهازك، ثم ارفع محتويات المجلد من Git، أو ارفع الملف المضغوط عبر GitHub Desktop/سطر الأوامر. لا تستخدم **Add file → Upload files** لرفع ملف ZIP فقط، لأن GitHub سيحفظه كملف مضغوط ولن ينشر محتواه، وقد لا يرفع المجلد المخفي `.github` عند النسخ اليدوي.

مسارات الأصول والصفحات نسبية، لذلك يدعم الموقع روابط مستودعات Pages مثل `https://YOUR-ACCOUNT.github.io/YOUR-REPOSITORY/` دون تغيير كود الأصول. يمكن أيضاً نشر محتويات `public/` كما هي على أي استضافة ثابتة.

## الشعار ورمز QR وعنوان الموقع

الشعار المستعمل هو شعار الزراعة النظيفة، ورمز QR المرفق محفوظ في `public/assets/images/clean-agri-qr.webp`. إعدادات الشعار والرمز ورابط الموقع في `site.config.json`. وجهة الرمز المعتمدة حالياً هي `https://info-samad.github.io/`.

بعد تأكيد رابط نشر هذه المنصة، ضع عنوانها الفعلي في `publicUrl` داخل `site.config.json` وأعد البناء. لا تخلط عنوان المنصة برابط الزراعة النظيفة إذا كان المستودع منشوراً على مسار آخر.

## تحديث المحتوى دون رفع الموقع كله

لا تعدّل الصفحة المولدة مباشرة. حرر ملف البيانات المطلوب فقط، ثم احفظه في المستودع. ينفذ GitHub Actions البناء والفحوص والنشر تلقائياً عند عمل commit إلى `main` أو `master`. خطوات تحرير المحاصيل والتحاليل والصور موجودة في [دليل تحديث المحتوى](content/دليل-تحديث-المحتوى.md).

- المحاصيل الجديدة: `research/crops.json`.
- نتائج تحليل دفعة السماد: `content/manure-product.json`؛ لا تظهر النسب ما لم تُدخل نتائج موثقة.
- صور الأقسام: ارفع الصورة وحدها إلى `public/assets/images/sections/`، ثم أضف وصفها ومسارها في `content/section-images.json`.
- البريد والهاتف: `site.config.json`.

بعد كل commit، لا حاجة إلى إعادة رفع مجلد المشروع أو ملف ZIP. راقب تبويب **Actions** حتى ينجح سير **نشر المنصة على GitHub Pages**.

## حدود المحتوى الزراعي

الحاسبات تضرب أو تقسم مدخلات المستخدم؛ لا تستخرج جرعة من اسم المحصول أو أعراضه. معدل العنصر والتوفر الموسمي للنيتروجين يجب أن يأتي من توصية ملائمة وتحليل موثق. جداول الطماطم والخيار مرجعية بحسب نظام الإنتاج والمصدر، وليست برنامجاً سورياً ثابتاً. لا تُفسر قيمة ppm على أنها وزن منتج، ولا تستخدم جداول الزراعة دون تربة في تربة البيت المحمي.

لا يُفسر حساب العناصر العضوية على أنه إذن بإضافة السماد إذا كانت الملوحة أو الفوسفور أو النضج أو السلامة غير مناسبة. لا تُحقن مادة عضوية خام أو شاي روث في التنقيط. كل تعديل رقمي يحتاج مصدره ووحدته وتاريخ مراجعته.

## الحقوق والـQR

تستخدم النسخة شعار الزراعة النظيفة ورمز QR المرفق، وتستعمل خط Noto Sans Arabic وDM Sans مثل الموقع المرجعي. وجهة رمز QR هي `https://info-samad.github.io/`، بينما عنوان نشر نسخة Pages يعتمد على إعدادات مستودع GitHub الذي ترفع إليه هذه الحزمة.

## مثال إضافة الكوسا والباذنجان

أضف الكائنين التاليين داخل المصفوفة `crops` في `research/crops.json` بعد التأكد من أن المراجع تدعم وجود المحصول ونظامه. لا تضع جرعة تسميد داخل سجل المحصول؛ السجل يصف السياق وأسئلة الفحص فقط:

```json
{
  "id": "zucchini",
  "name": "الكوسا",
  "category": "الخضر المكشوفة",
  "systems": ["حقول مكشوفة مروية", "بيوت بلاستيكية"],
  "focus": "ربط التغذية بانتظام الماء والصرف وحمل الثمار، مع فصل أثر الحرارة والملوحة عن نقص العناصر.",
  "checks": ["تحليل التربة وماء الري ومراجعة EC وطريقة القياس.", "تحديد النظام ونوع الوسط.", "فحص الجذور وانتظام الري قبل زيادة العناصر."],
  "sourceIds": ["fao-syria-2021", "fao-plant-nutrition", "fao-water-quality"]
}
```

```json
{
  "id": "eggplant",
  "name": "الباذنجان",
  "category": "الخضر المكشوفة",
  "systems": ["حقول مكشوفة مروية", "بيوت بلاستيكية"],
  "focus": "تقييم التغذية مع حمل الثمار وحرارة البيت وجودة ماء الري، وعدم تفسير ضعف العقد كتسميد فقط.",
  "checks": ["تحليل التربة والماء ومراجعة EC والصرف.", "فحص الجذور والملوحة وتجانس الري.", "تسجيل الصنف والمرحلة والحمل والمدخلات السابقة."],
  "sourceIds": ["fao-syria-2021", "fao-farming-systems", "fao-plant-nutrition"]
}
```

بعد الحفظ شغّل `python3 scripts/build_site.py` ثم `python3 scripts/check_site.py`. سيظهر المحصول تلقائياً في دليل المحاصيل، وخيارات نموذج السياق، والبحث والتصفية. إذا أردت جدول تسميد خاصاً به، لا تضفه إلى `crops.json`؛ أضف جدولاً ذا مصدر واضح إلى `research/greenhouse-schedules.json` مع تحديد هل هو للتربة أو للزراعة دون تربة ووحدة كل رقم.
