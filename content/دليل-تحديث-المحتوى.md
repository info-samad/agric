# دليل تعديل المنصة من واجهة GitHub مباشرة

## إضافة محصول أو تعديله من المتصفح

1. سجّل الدخول إلى GitHub وافتح المستودع الذي تنشر منه المنصة، وهو `info-samad/agri` إذا كان المستودع ما زال كما في لقطة الإعدادات السابقة.
2. تأكد أنك على الفرع المنشور `main` (أو `master` إذا كان هذا هو فرع النشر عندك). افتح مجلد `research` ثم ملف `crops.json`.
3. اضغط زر القلم **Edit this file**. ستظهر لك صفحة تحرير JSON.
4. ابحث داخل الملف عن المفتاح `"crops": [`؛ السجلات التي تليه هي المحاصيل. لتعديل محصول، غيّر الاسم أو النص المطلوب داخل سجله فقط. لإضافة محصول، انسخ سجلاً كاملاً من أول `{` إلى `}`، ثم الصقه داخل قائمة `crops` قبل قوس الإغلاق `]`، مع فاصلة `,` بين السجل الجديد والسابق.
5. غيّر `id` إلى رمز لاتيني فريد بحروف صغيرة وشرطة عند الحاجة، مثل `new-crop-name`؛ لا تكرر رمز محصول موجود. حدّث الحقول `name` و`category` و`systems` و`focus` و`checks` بحسب معلومات موثوقة. استخدم فئة موجودة كما هي: `الحبوب`، `الخضر المحمية`، `الخضر المكشوفة`، `الأشجار المثمرة والكروم`، `البقوليات الغذائية`، `الأعلاف`، أو `المحاصيل الحقلية والصناعية`.
6. في `sourceIds` اكتب معرّفات حقيقية موجودة ضمن قائمة `sources` في الملف أو في ملفات مصادر المشروع. لا تستخدم مثالاً شكلياً كمصدر. إذا أضفت مرجعاً جديداً، أضف سجله إلى قائمة `sources` بمعرّف فريد وعنوان ورابط مباشر موثوق. لا تكتب جرعات أو مواعيد تسميد في سجل المحصول؛ حقلا `focus` و`checks` أسئلة وملاحظات إرشادية لا توصيات تطبيق.
7. راجع التنسيق: علامات الاقتباس مستقيمة، الفاصلة تفصل بين عناصر القائمة، ولا تضع فاصلة بعد آخر عنصر. استخدم **Preview changes** لمراجعة الفرق ثم **Commit changes**. الأفضل أن تحفظ مباشرة إلى `main` أو `master`؛ إذا حفظت في فرع آخر، ادمج التغيير إلى فرع النشر أولاً.
8. افتح تبويب **Actions** في المستودع، واختر سير **نشر المنصة على GitHub Pages**. انتظر العلامة الخضراء؛ إذا فشل، افتح المهمة الحمراء واقرأ خطوة البناء أو الفحص التي توقفت. لا تعدّل `public/assets/js/crop-data.js` ولا `public/index.html` يدوياً؛ البناء يعيد توليدهما من ملفات المصدر.

هذا هو شكل سجل للتوضيح فقط؛ استبدل النصوص والمعرّف والمصدر قبل الحفظ، ولا تضف محصولاً أو ادعاءً بلا مرجع مناسب:

```json
{
  "id": "unique-latin-id",
  "name": "اسم المحصول",
  "category": "اختر فئة موجودة حرفياً",
  "systems": ["نظام الزراعة الموثق"],
  "focus": "سياق وأسئلة إرشادية بلا جرعة تسميد.",
  "checks": ["فحص التربة والماء والمرحلة."],
  "sourceIds": ["معرّف-مصدر-موجود-فعلاً"]
}
```

## حاسبة كمية السماد العضوي الحيواني

الحاسبة مفعّلة داخل `أدوات المزارع`، ويمكن الوصول إليها من رابط «احسب كمية الدفعة من تحليلها» في باب السماد. معادلتها تحسب **كتلة المنتج النظرية** اللازمة لتحقيق هدف عنصر كلي أدخله المستخدم بنفسه، من مساحة الحقل، ونسبة العنصر في تحليل الدفعة، ورطوبتها عند كون التحليل على أساس جاف. وتُظهر معها كميات N وP₂O₅ وK₂O الكلية المحمّلة في هذه الكتلة.

لصيانة الكود: بنية الحقول والشرح في `src/farmer-tools-section.html`؛ الحساب والتحقق من المدخلات في `public/assets/js/farmer-tools.js` ضمن `manureRequiredMass()`؛ الاختبارات الحسابية في `scripts/test_calculators.cjs`، واختبار نموذج المتصفح في `scripts/test_schedule_tabs.cjs`. بعد أي تعديل للكود، شغّل بناء الموقع واختباراته قبل حفظ التغيير.

هذه ليست جرعة موصى بها ولا تحسب N المتاح للمحصول تلقائياً. لا تستخدم N الكلي بوصفه N متاحاً للموسم الأول. يلزم تحليل ممثل للدفعة الحالية، وهدف عنصر مستقل صادر عن توصية مناسبة للحقل، ومراجعة الملوحة والنضج والسلامة الميكروبية والفوسفور وماء الري قبل التطبيق. لا تُدخل نسباً تقديرية من اسم الحيوان.

## تحديث تحليل المنتج أو صوره أو التواصل

- **تحليل الدفعة:** حرّر `content/manure-product.json`؛ أدخل القيم من تقرير مخبري فقط، وحدّث تاريخ التحليل وأساسه. قيمة `null` لا تظهر على الصفحة.
- **صورة قسم:** استخدم **Add file → Upload files** لرفع الصورة إلى `public/assets/images/sections/`، ثم أضف مسارها ووصف `alt` في `content/section-images.json`.
- **البريد والهاتف:** حرّر `contactEmail` و`contactPhone` في `site.config.json`.
- بعد حفظ الملفات في commit، يكفي رفع التغييرات التي عدّلتها؛ يقوم GitHub Actions بإعادة البناء ونشر مجلد `public` تلقائياً. لا ترفع ملف ZIP كل مرة.
