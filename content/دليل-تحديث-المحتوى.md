# تحديث الموقع من GitHub دون رفعه كاملاً

الموقع مبني من ملفات مصدر ومحتوى. لا تعدّل `public/index.html` مباشرة؛ فهو ملف ناتج عن البناء وقد يستبدل في النشر التالي. عدّل ملف البيانات المطلوب فقط ثم احفظ التغيير في GitHub. يبدأ GitHub Actions البناء والنشر تلقائياً عند الدفع إلى `main` أو `master`.

## إضافة محصول

افتح `research/crops.json` في GitHub واضغط زر القلم **Edit**. انسخ سجل محصول موجود داخل مصفوفة `crops`، غيّر `id` ليكون لاتينياً وفريداً، وأكمل الاسم والمجموعة والسياق ونقاط الفحص والمصادر. أضف فاصلة بين السجلات، ولا تضع جرعة تسميد في هذا الملف. اضغط **Commit changes**؛ لا تحتاج إلى رفع الموقع كله.

```json
{
  "id": "new-crop-id",
  "name": "اسم المحصول",
  "category": "الخضروات",
  "systems": ["تربة مكشوفة"],
  "focus": "ما يجب مراعاته لهذا المحصول.",
  "checks": ["تحقق من التربة والماء والمرحلة."],
  "sourceIds": ["معرّف-مصدر-موجود"]
}
```

استخدم معرّف مصدر موجوداً في سجل `sources`، أو أضف المرجع الموثق إلى ملف المصدر المناسب. يرفض فحص البناء أي معرّف غير معروف.

## تحديث نسب تحليل السماد

افتح `content/manure-product.json`، وأدخل فقط القيم الواردة في تحليل مخبري للدفعة. حدّث `analysisDate` و`analysisBasis` لبيان تاريخ التحليل وهل النسب على أساس الوزن المستلم أو المادة الجافة. الحقول الفارغة `null` لا تظهر كنسب على الموقع. الفوسفور والبوتاسيوم في الملف معرّفان على أساس P₂O₅ وK₂O؛ لا تضع قيماً محسوبة على أساس P وK دون تحويل موثق. لا تستخدم قيماً تقريبية مأخوذة من اسم الحيوان.

بعد **Commit changes** يعيد سير العمل بناء الصفحة وينشرها، ولا تحتاج إلى إرسال ملفات المشروع الأخرى.

## إضافة صورة إلى قسم

ارفع ملف الصورة إلى `public/assets/images/sections/` باستخدام **Add file → Upload files** في GitHub. ثم افتح `content/section-images.json` وأضف عنصراً داخل `images`:

```json
{
  "section": "organicManure",
  "file": "assets/images/sections/اسم-الصورة.jpg",
  "alt": "وصف واضح للصورة",
  "caption": "تعليق اختياري للصورة"
}
```

الأقسام المدعومة: `organicManure` و`greenhouseSchedules` و`cropDirectory` و`farmerTools` و`plantNutritionGuide` و`strategicCropRecommendations` و`diagnosisWizard` و`calculatorSection`. أضف الصورة وملف القائمة إلى الفرع نفسه؛ يمكن حفظهما في commit واحد. يجب أن يكون وصف `alt` مفيداً، وأن يكون مسار الصورة داخل `public`.

## تغيير البريد أو الهاتف

غيّر `contactEmail` أو `contactPhone` في `site.config.json` ثم اعمل commit. تظهر القيم كرابط بريد أو اتصال في تذييل الصفحة.

## كيف ترفع التعديلات عملياً؟

من GitHub Web: ارفع الصورة عند الحاجة، ثم حرر ملف JSON من زر القلم، واحفظ التعديل بـ **Commit changes**. من GitHub Desktop أو Git: اسحب نسخة المستودع محلياً، عدّل ملفاً واحداً أو أكثر، ثم **Commit** و**Push**. بعد ذلك افتح **Actions** وانتظر أن يصبح سير **نشر المنصة على GitHub Pages** أخضر. سير العمل يعيد بناء مجلد النشر تلقائياً؛ أنت ترفع التغيير الصغير فقط، وليس كامل الموقع.

لا تعدّل ملفات `public/index.html` أو `public/assets/js/crop-data.js` الناتجة يدوياً؛ عدّل ملفات `research/` أو `content/` أو إعدادات `site.config.json` ثم اترك سير العمل يبني المخرجات.
